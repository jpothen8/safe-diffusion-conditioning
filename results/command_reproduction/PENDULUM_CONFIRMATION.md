# Frozen Pendulum confirmation protocol

Written after development and before generating confirmation states or proposals. This is an existence study of useful examples selected through development, not an unbiased estimate over all tasks or constraints. Earlier Push-T results and all Pendulum development settings remain reported.

## System, policy and safety

Use Gym 0.26.2 Pendulum-v1 with its unchanged native dynamics and reward, dt=0.05 s. The public TD3 actor is extracted without observation normalization, with the saved 400/300 ReLU architecture and physical action = 2*tanh output. The untouched environment/actor smoke and the vectorized dynamics agree exactly over 2,000 steps. The simulator snapshots are (angle, angular velocity); these are the complete physical state of this deterministic system.

The base policy is the frozen 146,956-parameter state DDPM in `assets/pendulum_diffusion.pt`, SHA256 `ad34c0f1f53bb66cdc9379b5033b06a466cfeb97742a0d6100714ccbf0b35e99`. It was trained once on 640 complete 200-step episodes from the actor and its reflection. Initial-state groups, including both expert episodes, were split 256/32/32 before making overlapping chunks. Observation statistics and torque scaling use training episodes only. There are 96,768 training chunks. Sampling uses 100 DDPM steps, cosine beta schedule, epsilon prediction, fixed-small variance, normalized sample clipping, then physical clipping to [-2,2]. All of these operations define p(A|s). Inputs are (cos theta, sin theta, velocity); no behavior label or safety constraint is supplied to p.

The chunk contains 12 torques and lasts **0.6 s**. Execute all 12 controls, followed by the same frozen deterministic public TD3 controller through control 200 (**10 s total**). The temporary actuator admissibility restriction is active only for the initial 0.6 s. It models a supplied, time-limited one-sided torque envelope. This is not a whole-episode state-safety certificate or a natural built-in Pendulum hazard. Both methods receive exactly the same state, horizon, bounds and continuation. Native reward is `-(wrap(theta)^2 + .1*velocity^2 + .001*torque^2)`; it is never altered to favor either method.

Two co-primary examples are fixed: C_minus = [-2,0]^12 and C_plus = [0,2]^12. Both have nonempty interiors and useful policy support in development. This is a full-horizon convex set. Its global Euclidean projection is exactly elementwise clipping, the unique minimizer of sum_t (U_t-A_t)^2. There is no iterative solver, local optimum, shortened lookahead or weaker safety information. Numeric output verification tolerance is 1e-7 Nm. The added safety boundary is zero torque, distinct from the pre-existing physical saturation boundaries +/-2; the base sampler itself can have atoms at physical bounds.

## Arms and frozen finite refinement

For each state and replicate, independently draw 64 complete diffusion proposals. Save every proposal. A returns the **first feasible** proposal; no reward is evaluated for choosing it. Record refusals, actual proposals and logical first-accept cost. Conditional on budget success, A has q = p*1_C/Z. B projects proposal zero. Already feasible proposals are unchanged. Shared proposal zero gives a paired estimate with correct marginals. Every severity reuses the same bank. A second acceptance, where available, is used only as an independent conditional distribution diagnostic, never as a better-reward replacement.

Arm R implements the supplied draft's projected Langevin update (gamma=1/2), initialized with B. Use the same frozen epsilon network, with VE conversion y=x_VP/sqrt(alpha_bar), score_y = -epsilon(sqrt(alpha_bar)*y,t,obs)/sqrt((1-alpha_bar)/alpha_bar). Refine at timesteps 20, 5, 0 for 256, 256, 512 iterations respectively. At each level alpha_k = .15*sigma^2/(1+k/64)^.6. Project each iteration in normalized coordinates onto the exact same box. Uniform torque scaling by 2 leaves Euclidean projection unchanged. This schedule was selected from three disclosed development schedules and is fixed for both signs.

R is a finite implementation inspired by the draft's annealed refinement, **not an exact conditional sampler**. Its learned score, nonzero final noise, finite mixing and output law are not assumed to equal the actual DDPM conditional law. Report its discrepancy from rejection and its cost. Empirical-measure asymptotic claims in the draft are not invoked as an endpoint guarantee here.

## Frozen sample sizes, seeds and decisions

Draw 64 independent held-out snapshots with RNG seed 71000: theta = pi + Uniform[-.05,.05], velocity = Uniform[-.05,.05]. These seeds and states are disjoint from data generation and development; this is intentionally a local neighborhood of the downward symmetry state, not the standard uniform reset benchmark. Use 8 paired replicates/state (512 outputs/arm/example), budget 64. Proposal generation seed is 72000+state index; refinement seed is 73000+example index. Seeds are not changed following outcomes. All states and replicates are retained, including low acceptance, poor behavior and failures.

Primary metric: native undiscounted 200-step return, higher is better. Minimum useful gain: **25 return points**, equivalent to 0.125 mean reward per control. An example passes if mean paired gain >=25, its interval excludes zero, and all output feasibility/refusal checks pass. Compute paired per-state means, then bootstrap 64 state clusters with replacement 20,000 times using seed 74000. Report 98.75% two-sided intervals for the four comparisons (A-B and R-B, each sign); Bonferroni gives at least 95% family coverage under bootstrap approximation. Report ordinary 95% intervals too. This is evidence over fresh states/seeds for a selected setting; no cross-task or universal superiority claim is made.

Secondary metrics: zero-torque boundary concentration (any coordinate within 1e-5 Nm), physical saturation, signed first-chunk displacement, coherent mode occupancy (mean chunk torque < -1, > 1, or intermediate), acceptance by state, all safety violations, and stabilization time. Stabilization is the first start of 20 consecutive controls with wrapped |theta|<.1 rad and |velocity|<.5 rad/s. Nonstabilized episodes count as failures and receive capped time 10 s; Pendulum itself has no success terminal event. Native return includes all episodes without selection.

Distribution diagnostics: pooled RMS-normalized action RBF MMD, kernel exp(-mean(((A-B)/2)^2)/(2*.1^2)), versus the conditional reference and versus its independent second-accept sample. This is a finite-sample diagnostic of action distribution discrepancy, not a bound on total variation or proof of conditional correctness. Independent q samples establish its sampling-noise scale. Reward similarity alone is not used to claim distributional equality.

Before execution, the runner hashes this protocol, its config, all implementation sources, the model and expert. It saves states, all proposals, accept masks, selected indices, actual output chunks, full rollouts, costs and summaries. It independently replays a fixed subset in the untouched Gym environment. A failure is reported separately rather than silently replaced. Reference cost is reported without forcing cost matching to projection.

## Precision correction after the first execution

The first run's independent Gym replay failed despite all torque outputs being feasible. Diagnosis: NumPy retains float32 in array torque products, while Gym's scalar torque arithmetic promotes to float64. Tiny per-step differences become large under open-loop replay near an unstable upright state. Casting torques to float64 in the vectorized dynamics makes stored-action replay agree **exactly** with Gym. A direct recomputation of the negative conditional return changed the mean by only 2.4e-8 points.

Preserve the full first run in `results/pendulum/confirmation_initial_precision/` and the original dynamics in `records/pendulum_initial_dynamics.py`. Rerun the identical locked states, proposal/refinement seeds, checkpoint, metric, thresholds and analysis with this arithmetic correction only; verify that proposal and output chunks are unchanged. No task, safety, model or sampler choices are retuned using confirmation outcomes. The generated training episodes and frozen checkpoint are retained; their original collection arithmetic is recorded rather than silently regenerated. The corrected run is the reported confirmation.
